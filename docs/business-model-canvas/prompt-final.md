# Prompt final · Business Model Canvas Interactivo

Utiliza Archify para representar la información definida por el equipo para **TI: Soporte en Acción**. No inventes funcionalidades, indicadores medidos, ingresos ni decisiones técnicas. La fuente de contenido es el README de esta práctica, transcrito y organizado a partir del encargo del equipo.

Crea un HTML estático autónomo en `docs/business-model-canvas/index.html`, con siete componentes conectados: problema, usuarios, propuesta de valor, solución, procesos, tecnologías y resultados. Diferencia roles de usuarios y personajes. Muestra la brecha entre teoría y práctica y el valor de practicar TI en una simulación segura y gamificada.

Identifica Unity como videojuego 2D, Flutter como consulta móvil y React / PWA como gestión y seguimiento. Incluye API, Keycloak, MongoDB, Docker, Grafana, Git, GitHub y GitHub Pages con las funciones acordadas. Respeta exclusivamente este conjunto de tecnologías.

Conserva la narrativa: Alex empieza en NovaTech Solutions; Martín es mentor, Richar se especializa en redes e infraestructura y seguridad, Marco en desarrollo; Sofía y Elena son personajes secundarios; un Saboteador interno provoca fallas.

Documenta completos los flujos del jugador, contenido y autenticación, las mecánicas de XP, niveles, insignias, logros, estadísticas y retroalimentación, y los beneficios esperados. Complementa el Canvas con una arquitectura interactiva usuario → Keycloak → tres aplicaciones → API → MongoDB.

Usa relaciones legibles, controles de exploración, temas y exportación del visor. Mantén el contenido en español y declara el fallback inglés de sus controles. Conserva una primera versión real y una final con al menos cinco modificaciones documentadas y capturas PNG obtenidas del navegador. Valida cada especificación con perfil showcase y conserva los comprobantes. Prepara el acceso en GitHub Pages sin afirmar que está publicado hasta verificar el despliegue.
